ブランド立ち上げを速くする仕組み — 設計書 v1 (2026-10-01)

読者: ジョニー。目的: 副業でブランドを増やすたびに、YouTube・TikTok・Instagram・X の登録で詰まらないようにする。各社のロボット判定や回数制限をかいくぐる仕組みは作らない (規約違反で、育てたアカウントごと止まるため)。

0. 結論

  • 今日詰まった原因は「ブランドごとに、ゼロから新しい身元を作ろうとした」こと。 各社とも「1人が複数ブランドを持つ」ための公式の近道を用意している。それを使えば、新規登録そのものが要らない所が多い
  • 身元は「持ち主1人」に集約し、ブランドは各社の公式機能でその下に生やす:
    • YouTube: 1つの Google アカウントの下にブランドチャンネルを最大100まで。新規の Google アカウントは不要 (個人の Gmail の下にある「絶滅職種図鑑」「街で宅建」と同じ作り)
    • Instagram: 既存アカウントから「アカウントを追加 → 新しいアカウントを作成」。新しい電話番号もメールも不要。1つのアプリで最大10アカウントまで同時ログイン
    • X: 1つの電話番号を最大10アカウントで共用可。メールだけブランドごとに分ける (zukan.page の転送アドレス)
    • TikTok: いちばん硬い。 電話番号・メール・Google/Apple 等のログインは、どれも1アカウントにしか使えない。ブランドごとに「まだ TikTok で使っていないメール」で登録する。電話番号を求められたら、ブランド用の正規の2回線目が要る
  • 人の手が要るのは、ブランド1つにつき最初の約10分だけにする (確認コード・パスワード・電話番号)。名前の空き確認・メールの転送・アイコン・自己紹介・投稿・分析は、私の仕組みで自動にする
  • 投稿の自動化: YouTube と Instagram は自作の仕組みで可能。TikTok は自作での公開投稿が規約で閉じている (「自分のアカウントに投稿するためのツール」は不可と明記) ので、審査済みの予約投稿ツール (Buffer か Metricool) を通す

3. 作るもの (開発)

  1. 名前の空き確認の道具 (brand-name-check): 候補を渡すと4社の空きを一覧にする。今日手でやった確認 (公開ページの表示で判定) をまとめるだけ
  2. ブランド一式の生成 (brand-kit): 名前・世界観の一文から、自己紹介 (各社の字数内)・アイコン・バナー・第1話の投稿文を作る。今回の Wonder Zukan の一式を型にする
  3. 登録の手順書を1画面に (brand-launch のページ): ブランドごとに、ジョニーが押す所・入れる所だけを順に並べた iPhone で見られるチェックリスト。各社の登録画面へのリンクつき
  4. 投稿の配線: Metricool か Buffer の API に、動画・投稿文・予約時刻を渡す。YouTube は自作 (審査を申請) でもよい
  5. (任意) メール転送の自動化: 転送アドレスの作成を API でできるようにする (Cloudflare Email Routing への移行か、Porkbun の API で可能か要確認)

作らないもの: ロボット判定の突破、使い捨て SMS 番号、指紋偽装ブラウザ、アカウントの一括自動作成、自分のアカウント同士の押し上げ。

4. Wonder Zukan の今からの進め方

  • YouTube: wonder@zukan.page の Google アカウントは作成済み。このアカウントでブランドチャンネルを作る (Codex 用のコマンドは用意済み)。または個人の Gmail の下にブランドチャンネルとして作ってもよい (こちらは新規登録が要らない)
  • Instagram: 個人の Instagram アプリから「アカウントを追加 → 新しいアカウントを作成」で wonderzukan。電話・メール不要
  • X: wonder@zukan.page + 今の電話番号 (10アカウントまで共用可) で登録
  • TikTok: 回数制限が解けてから、Web で wonder@zukan.page の登録をもう一度。電話番号を求められたら、2回線目 (povo など) を用意する。既存の TikTok を消す必要はない

5. 判断が要ること

  1. 2回線目の電話番号を持つか (povo の基本料0円プランが最安。180日ごとに少額の課金)
  2. 予約投稿ツールを Metricool (ブランドが増えるほど割安) と Buffer (チャンネル単位、始めやすい) のどちらにするか。どちらも有料
  3. 開発の順番: 1 (名前確認) → 3 (手順書) → 2 (一式生成) → 4 (投稿の配線) を提案
